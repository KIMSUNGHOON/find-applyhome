# 청약홈 미계약 세대 스캐너

청약홈 「분양권 정보(전매제한 등) 안내」 페이지는 동·호수를 하나씩 골라야만 세대 정보를 볼 수 있다.
이 도구는 한 단지의 전 동·전 호를 자동으로 훑어, 분양권 정보가 등록되지 않은 세대를 한 화면에 모아 보여준다.

## 실행

```bash
python3 app.py
```

브라우저가 `http://127.0.0.1:8765` 로 열린다. 설치할 패키지는 없다 (표준 라이브러리만 쓴다).

## 쓰는 법

1. 단지명을 검색해 대상 단지를 고른다 (결과가 10건을 넘으면 `더 보기`로 이어 본다)
2. `전체 스캔`을 누른다 — 242세대 기준 약 16초
3. **주황색 칸이 정보없음 세대**다. 칸을 누르면 아래에 상세가 뜬다
   - 격자 헤더 아래줄이 타입(`84A`), 칸 안의 `특`/`일` 이 그 세대 당첨자의 청약 유형이다
   - 빈칸은 청약홈에 등록되지 않은 호수다 (조합원·임대 등 일반분양 외 물량)
4. 격자 위 **타입별 현황표**로 어느 타입에 미계약이 몰렸는지 본다
5. 그리드 아래 `정보없음 N세대` 표가 최종 결과다. `CSV로 내려받기`로 저장한다

## 판정 기준

청약홈은 분양권 정보가 없는 세대를 조회하면 다음 경고창을 띄운다.

> 해당 [동:xxx, 호:xxx]에 대한 분양권 세부 정보가 없습니다.

이 도구는 청약홈 스크립트와 **같은 조건**(상세 응답의 `id="houseManageNo"` 가 비었는지)으로 판정한다.
즉 손으로 동·호수를 하나씩 찍어보는 것과 결과가 같고, 그 작업을 전수 자동화한 것이다.

**주의** — `정보없음`은 "청약홈에 분양권 정보가 등록되지 않았다"는 사실만 뜻한다.
미계약·부적격 세대일 가능성이 높지만, 사업주체가 계약 건을 아직 등록하지 않았을 수도 있다. 참고용으로만 쓸 것.

`정보없음` 응답에는 주택형·공급유형이 실려 오지 않는다. 목록의 `타입(참고)` 는
같은 동·같은 라인(호수 끝 두 자리)의 정보있음 세대에서 빌려온 값이다.

### 타입과 공급유형

타입(주택형)은 라인마다 고정이라, 미계약 세대의 타입도 같은 라인의 계약 세대에서 알아낼 수 있다.
이렇게 채운 타입별 세대수가 공고와 정확히 일치하는 것을 두 단지에서 확인했다
(상봉 센트럴 아이파크 242세대, 장위 푸르지오 마크원 23개 동 1032세대).
어긋나는 단지가 있으면 현황표 위에 경고가 뜬다.

공급유형(특별/일반)은 **세대의 속성이 아니라 그 세대에 당첨된 사람의 청약 유형**이다.
그래서 미계약 세대에는 값이 없고, 같은 라인 안에서도 층마다 섞인다. 격자에서 미계약 칸이 비어 있는 이유다.
타입 단위 배정 세대수는 공고에서 가져와 현황표에 보여준다.

격자의 빈칸은 청약홈이 호 목록에 넣지 않은 호수다. 조합원분·임대 등 일반분양 대상이 아닌 물량으로 보인다.
상봉의 경우 호 목록 242세대가 공고의 공급규모 242세대와 정확히 같았다.
즉 스캔은 처음부터 특별공급·일반공급 세대 안에서만 이뤄진다.

공고는 APT 전용 엔드포인트(`selectAPTLttotPblancDetail.do`)에서 가져온다.
오피스텔·도시형은 주소가 달라 조회에 실패하는데, 그때는 현황표를 스캔 결과만으로 만들고
`공고 대조 불가` 로 표시한다. 스캔 자체는 영향받지 않는다.

## 구조

| 파일 | 책임 |
|---|---|
| `applyhome.py` | 청약홈 API 호출과 응답 파싱. 네트워크를 다루는 유일한 곳 |
| `grid.py` | 호수 → 층·라인 격자 산출, 주택형 축약·전용면적 추출 |
| `scanner.py` | 단지 1개 전수 스캔. 동시성·간격·중단 제어 |
| `server.py` | HTTP 라우팅, SSE 스트리밍, CSV 생성 |
| `app.py` | 진입점 |
| `static/index.html` | UI 전체 |

## 테스트

```bash
python3 -m unittest discover -s tests -v                  # 저장된 응답으로만 (네트워크 불필요)
APPLYHOME_LIVE=1 python3 -m unittest tests.test_live -v   # 청약홈에 실제로 붙는 회귀 테스트
```

기본 실행은 86건이며 그중 라이브 2건은 건너뛴다.
라이브 테스트는 2026-07-24 실측값(상봉 센트럴 아이파크 101동 정보없음 10건)을 기준으로 한다.
실패하면 청약홈 데이터가 갱신된 것이므로 `tests/test_live.py` 의 `EXPECTED_EMPTY_101` 을 갱신한다.

## 청약홈 서버 배려

공공 사이트이므로 동시 요청 4개, 요청 간 0.1초 간격, 실패 시 3회 재시도(0.5s → 1s → 2s)로 제한한다.
값은 `scanner.scan_complex` 의 `max_workers`·`delay` 인자와 `applyhome.RETRIES` 에 있다.
