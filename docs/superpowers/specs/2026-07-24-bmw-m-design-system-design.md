# BMW M 디자인 시스템 적용 — 설계

작성일: 2026-07-24
선행 스펙: [2026-07-24-type-and-supply-breakdown-design.md](2026-07-24-type-and-supply-breakdown-design.md)

## 1. 배경

사용자가 BMW M 마케팅 사이트의 디자인 시스템 명세를 제공하고 스캐너 UI에 적용할 것을 요청했다.
기능은 그대로 두고 `static/index.html` 의 시각 언어만 교체한다.

### 1.1 원본 시스템과의 근본적 차이

BMW M 시스템의 전제는 **"브랜드 에너지는 풀블리드 자동차 사진에서 나오고 UI 크롬은 물러선다"** 이다.
이 도구에는 사진이 없다. 그대로 옮길 수 없는 항목이 셋 있다.

| 원본 | 이 프로젝트에서의 처리 |
|---|---|
| 풀블리드 자동차 사진이 시각적 주인공 | **격자가 사진의 자리를 대신한다.** 242개 칸이 색으로 채워지는 화면이 이미 이 도구의 주인공이다. 풀블리드로 크게 배치하면 원본의 밴드 리듬(주인공 → spec 테이블 → 주인공)이 성립한다 |
| UPPERCASE 디스플레이 헤드라인 | 한글에는 대문자가 없다. **한글은 weight 700 + 자간**으로 "각인된" 느낌을 내고, 영문·숫자 라벨(`SCAN`, `CSV`, `84A`)만 대문자 + 1.5px 트래킹을 적용한다 |
| BMW Type Next Latin | 라이선스 폰트이고, 웹폰트 CDN을 붙이면 이 프로젝트의 의존성 제로 원칙이 깨지고 오프라인에서 무너진다. **원본 스펙이 명시한 fallback 스택**(`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`)을 쓴다. 한글은 Apple SD Gothic Neo 가 300/700 을 지원해 heavy display + light body 대비가 성립한다 |

## 2. 목표와 비목표

### 목표

- 순흑 캔버스 위 흰 타이포그래피, heavy(700) 디스플레이 + light(300) 본문 대비를 적용한다.
- radius 0 을 전면 적용한다.
- 격자 데이터 색을 BMW 팔레트로 통일한다.
- M 삼색 스트라이프를 브랜드 마커로 도입한다.
- 96px 섹션 리듬으로 화면을 재구성한다.

### 비목표 (YAGNI)

- 자동차 사진, 웹폰트 CDN
- 애니메이션·트랜지션 (원본 스펙도 "not in scope")
- 라이트 모드 — BMW M 은 라이트 모드 마케팅 표면이 없다. 현재 `prefers-color-scheme` 대응 CSS 도 제거한다
- 파이썬 코드 변경 일체

## 3. 토큰

CSS 변수로 정의하고 인라인 hex 를 쓰지 않는다.

### 3.1 표면

| 변수 | 값 | 용도 |
|---|---|---|
| `--canvas` | `#000000` | 페이지 바닥 |
| `--surface-soft` | `#0d0d0d` | spec 셀 배경 |
| `--surface-card` | `#1a1a1a` | 카드, 입력창 |
| `--surface-elevated` | `#262626` | 중첩 카드 |
| `--cell-idle` | `#141414` | 격자의 빈 칸·미조회 칸 (7.1절) |
| `--hairline` | `#3c3c3c` | 1px 구분선 |

### 3.2 텍스트

| 변수 | 값 | 용도 |
|---|---|---|
| `--on-dark` | `#ffffff` | 헤드라인, 주요 텍스트 |
| `--body-strong` | `#e6e6e6` | 강조 본문 |
| `--body` | `#bbbbbb` | 기본 본문 |
| `--muted` | `#7e7e7e` | 캡션, 각주 |

### 3.3 M 삼색 — 브랜드 전용

| 변수 | 값 |
|---|---|
| `--m-blue-light` | `#0066b1` |
| `--m-blue-dark` | `#1c69d4` |
| `--m-red` | `#e22718` |

4px 스트라이프에만 쓴다. 버튼 배경이나 표면 채우기로 쓰지 않는다.

### 3.4 데이터 색

격자 칸의 상태를 나타낸다. 브랜드 마커가 아니라 **데이터 시각화 축**이다.

| 변수 | 값 | 뜻 |
|---|---|---|
| `--data-empty` | `#e22718` | 정보없음 (미계약·부적격 추정) |
| `--data-special` | `#1c69d4` | 정보있음 · 특별공급 |
| `--data-general` | `#6e6e6e` | 정보있음 · 일반공급 |
| `--data-error` | `#f4b400` | 조회실패 |

미계약이 가장 눈에 띄어야 한다는 원칙은 그대로다. M 레드가 화면에서 가장 강한 색이다.
조회실패를 warning 노랑으로 옮겨 미계약 빨강과 겹치지 않게 했다.

M 삼색과 hex 가 겹치지만 맥락이 다르다 — 하나는 4px 브랜드 스트라이프, 하나는 데이터 칸이다.
값은 `--m-*` 를 재참조하지 않고 `--data-*` 로 따로 정의한다. 나중에 한쪽만 바꿀 수 있어야 한다.

## 4. 타이포그래피

폰트 스택: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Apple SD Gothic Neo", sans-serif`

| 용도 | 크기 | 굵기 | 자간 | 적용처 |
|---|---|---|---|---|
| 페이지 타이틀 | 56px | 700 | -0.5px | `청약홈 미계약 세대 스캐너` |
| 섹션 헤드 | 32px | 700 | -0.3px | `타입별 현황`, `정보없음 18세대` |
| spec 값 | 32px | 700 | 0 | 현황표 세대수 |
| 동 이름 | 20px | 700 | 0 | `101동 · 119세대` |
| 라벨 | 14px | 700 | **1.5px** | `SCAN`, `SEARCH`, 표 헤더, 단계 번호 |
| 본문 | 16px | 300 | 0 | 안내 문구, 설명 |
| 작은 본문 | 14px | 300 | 0 | 검색 결과 메타, 상태 |
| 캡션 | 12px | 400 | 0.5px | 각주, 범례 |

**본문은 300 을 넘기지 않는다.** 400 이나 500 으로 올리면 유럽식 엔지니어링 톤이 마케팅 톤으로 바뀐다.
디스플레이는 700 아래로 내리지 않는다. 이 대비가 시스템의 서명이다.

한글 헤드라인에 음수 자간(-0.5px, -0.3px)을 준다. 원본 스펙이 Inter 대체 시 권고한 값이며,
한글에서도 큰 크기에서 자간이 벌어져 보이는 것을 잡아준다.

## 6. 컴포넌트 매핑

| 원본 컴포넌트 | 이 화면의 대응 | 명세 |
|---|---|---|
| `m-stripe-divider` | 페이지 최상단 | 높이 4px, `linear-gradient(90deg, m-blue-light 0 33%, m-blue-dark 33% 66%, m-red 66% 100%)` |
| `spec-cell` | 타입별 현황 셀 | 배경 `--surface-soft`, radius 0, 패딩 24px. 값 32px/700, 라벨 14px/700/1.5px, 보조 12px muted |
| `button-primary-outline` | `SEARCH`, `SCAN`, `더 보기`, 재시도 | 배경 투명, 1px `--on-dark` 테두리, 높이 48px, 패딩 0 32px, radius 0, 라벨 14px/700/1.5px |
| `text-input` | 단지명 입력, 시도 선택 | 배경 `--surface-card`, 1px `--hairline`, 높이 48px, radius 0. 포커스 시 테두리 `--on-dark` |
| `category-tab` | 검색 결과 항목 | 라디오 숨김. 선택 시 좌측 2px `--on-dark` 바 + 텍스트 흰색. 비선택은 `--body` |
| `caption` | 범례, 각주, 안내 | 12px/400/0.5px, `--muted` |
| `footer` | 하단 안내 문구 | `--canvas` 유지, 상단 1px hairline |

원형은 쓰지 않는다. 이 화면에는 캐러셀도 아이콘 버튼도 없어 `rounded.full` 예외가 발생하지 않는다.

## 7. 격자

**radius 0 을 격자 칸에도 적용한다.** 현재 3px 라운딩을 제거한다.
사각형 실루엣이 이 시스템의 정체성이고, 격자에는 "정밀 계측" 느낌이 잘 맞는다.

- 칸 크기 30 × 24px 유지
- 칸 간격 2px — 각 칸이 독립된 사각형으로 읽히게 한다. 사이로 드러나는 검은 캔버스가 경계다
- 채워진 칸은 테두리 없이 배경색만으로 구분한다
- 글자(`특`/`일`)는 11px / 700, 흰색
- 미계약·실패 칸은 글자 없음 (공급유형이 존재하지 않는다)

### 7.1 빈 칸을 지우지 않는다

격자의 빈 칸은 **청약홈에 등록되지 않은 호수**(조합원·임대 등 일반분양 외 물량)를 뜻하는
의미 있는 정보다. 테두리를 모두 없애면 빈 칸이 검은 캔버스에 녹아 사라지고 격자 구조가 무너진다.

빈 칸에는 `#141414` 배경을 준다. 캔버스(`#000`)보다 한 단계 밝아 자리는 보이되,
데이터 칸(빨강·파랑·회색·노랑)과는 확연히 구분되어 눈길을 끌지 않는다.

스캔 전 아직 결과가 오지 않은 칸도 같은 `#141414` 로 그려 두고, 결과가 도착하면 데이터 색으로 덮는다.
진행 중인 격자가 서서히 채워지는 모습이 그대로 유지된다.

층·라인 헤더는 `--muted` 12px, 타입 헤더는 14px/700/1.5px `--body`.

## 8. 유지하는 것

기능은 하나도 바꾸지 않는다.

- 스캔 로직, 판정 규칙, 라인→타입 유추, 공고 교차 검증, CSV, 실패 재시도, 중단
- SSE 이벤트 처리, `state` 구조
- 파이썬 파일 일체 (`applyhome.py`, `grid.py`, `scanner.py`, `server.py`, `app.py`)

`static/index.html` 의 CSS 와 마크업, 그리고 렌더링 함수가 만들어내는 HTML 문자열만 바뀐다.
JS 로직(계산·집계·이벤트)은 그대로다.

## 9. 테스트

이 작업은 파이썬을 건드리지 않으므로 **기존 테스트 86건이 그대로 통과해야 한다** (라이브 2건 skip).
테스트가 깨지면 UI 작업이 범위를 벗어난 것이다.

화면 검증은 브라우저에서 한다.

| 항목 | 기대 |
|---|---|
| 상봉 스캔 | 242세대 / 정보없음 18건 — 값이 이전과 같다 |
| 격자 칸 수 | 특별 92 · 일반 132 · 미계약 18 |
| 데이터 색 | 미계약 `rgb(226, 39, 24)`, 특별 `rgb(28, 105, 212)`, 일반 `rgb(110, 110, 110)` |
| radius | 모든 요소가 `0px` |
| 빈 칸 | `rgb(20, 20, 20)` — 캔버스와 구분되어 자리가 보인다 |
| M 스트라이프 | 페이지 최상단에 4px 높이로 존재 |
| 타이포 대비 | 타이틀 700, 본문 300 |
| CSV | 이전과 동일하게 내려받아진다 |
| 장위(23개 동) | 가로 배치 유지, 18개 타입 현황표 |
